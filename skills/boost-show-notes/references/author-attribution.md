# Author attribution patterns

Author credit is the part of the show notes Ulrikke cares most about getting right. The community is small and tight — getting someone's name wrong (or missing them entirely) is the difference between "thanks for the shoutout" and a quiet annoyance.

## When to add `by Author`

Add `by [Author Name]` when there's a clear human (or a small named team) responsible for the work. Skip the suffix entirely when:

- The piece is Microsoft official documentation (Microsoft Learn, learn.microsoft.com URLs).
- The piece is on the Microsoft Power Platform blog and has no individual byline.
- The author cannot be determined with confidence — better to mark `[CHECK AUTHOR]` than guess.

## Decoding names from handles

### GitHub usernames

The repo owner's display name is usually on their GitHub profile. Examples:

- `ToluVictor/canvas-apps-tools` → profile name is **Tolu Victor**
- `nickmeron/Dataverse-MCP-Server` → profile name is **Nir Meron**
- `microsoft/power-cat-skills` → no individual; credit `the Power CAT team`

When in doubt, fetch the GitHub profile page to confirm.

### LinkedIn slugs

LinkedIn vanity URLs are tricky because the slug format varies:

- `firstname-lastname-numeric` is the most common (`gasenko-valentin` → Valentin Gasenko, surname-first slug)
- `firstnamelastname` concatenated (`jukkaniiranen` → Jukka Niiranen)
- `valentinicola` looks like "Valentin Icola" but is actually **Nicola Valenti** (Italian convention — verify against the profile name displayed on the post)

Always check the profile name on the page, not just the slug. The slug is unreliable.

### Shorthand expansion

Ulrikke uses host nicknames in OneNote that need expanding for the published notes:

- `Josh and Charles` → **Charles Sexton and Josh Giles** (the order also flips — it's the alphabetical/age convention in their videos)
- `Scott` → **Scott Durow**
- `Jukka` → **Jukka Niiranen**
- `Nikita` → **Nikita Polyakov**

When you see a single first name and the context is Power Platform community, you can usually find a unique match. If multiple people in the community share a first name, mark `[CHECK AUTHOR]`.

## Name correction

Common typos and misspellings to watch for:

- "Resa Dorani" → **Reza Dorrani** (two r's, two n's)
- "Ana Black" → **Ania Black** (with an i)
- "Howdang Rashid" → verify this is correct (looks like it could be a stylization of "Hawdang" or similar)

Don't silently "correct" names without confirming. When uncertain, fetch the source page to see how the author's name is rendered there, and use that exact rendering.

## Team and group credits

When the work is from a team rather than a person, use `by the [Name] team`:

- `by the Power CAT team` — Power CAT (Microsoft's Customer Advisory Team) repos and posts
- `by the Microsoft Power Platform team` — corporate posts without an individual byline (but check — most Power Platform blog posts DO have an individual byline at the top)

## Multiple authors

Use natural English:

- Two authors: `by Charles Sexton and Josh Giles`
- Multiple: `by Charles Sexton, Josh Giles, and Daniel Christian` (Oxford comma — match the source page if it differs)

## When the author is also a host

If the work is by Nick or Ulrikke themselves (e.g., the EP83 Color Cloud workshop credit `by Nick and Ulrikke`), use the first names only — no surnames, since this is their own podcast.
